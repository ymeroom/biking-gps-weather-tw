## 你要做的事（一句話版）

日本版 `biking-gps-weather` 的台灣分身：手機網頁，騎車時藍點跟著 GPS，疊上**中央氣象署（CWA）觀測雷達回波圖**，
可播放過去 2–3 小時的動畫看雨帶往哪移動。未來那段等你申請 CWA opendata 免費 API key 後，
再加「路線前方鄉鎮未來 1–3 小時降雨預報」文字面板。

## 背景和動機

日本版靠 JMA 免費公開的「未來 2 小時雷達預報圖磚」。**台灣沒有等價的東西**——
CWA 只有免費的觀測合成回波圖（`CV1_3600_*.png`，每 10 分鐘），沒有免費公開的未來雷達動畫。
所以台灣版本質不同：v1a 是「即時＋過去雨帶追蹤」，v1b 的「未來」是文字預報不是雷達動畫。

## 技術驗證（已確認）

- CWA 觀測合成回波圖：`https://www.cwa.gov.tw/Data/radar/CV1_3600_YYYYMMDDHHMM.png`
  - 3600×3600 PNG，每 10 分鐘一張，免金鑰、免 CORS 顧慮（`<img>` 載入）
  - 時刻清單在 `https://www.cwa.gov.tw/Data/js/obs_img/Observe_radar.js`（`RadarImg.Tab0.Area0.size0`）
  - 是**固定地理範圍的整張圖**，不是 slippy tile → 用 Leaflet `L.imageOverlay(url, bounds)` 疊，bounds 要校準
- CWA opendata：datastore JSON API（`F-*` 預報類 demo key 可用）；雷達／QPE／QPF 影像類**不走這個 API**，
  要正式註冊 key ＋ 檔案下載服務。v1b 再處理。
- RainViewer 在台灣：有資料但常常 0 個未來影格、解析度低——不採用。

## 具體步驟

### === v1a（現在做，不需 key）===

### Step 1：從日本版複製骨架
- 做什麼：新資料夾 `D:\biking gps weather-tw`（或 `D:\biking-gps-weather-tw`），
  複製日本版的 `index.html` 為基礎，改標題、manifest、README。保留 GPS 藍點、方向三角形、
  精度圈、速度、Wake Lock（含 iOS 偵測）、深色底圖 CSS filter、跟隨/回到現在按鈕、幽靈點的幾何函式。
- 產出：能本機 `python -m http.server` 開、有 OSM 底圖與 GPS 邏輯的空殼。
- 注意：預設地圖中心改台灣（約 23.8, 121.0，zoom 8）。

### Step 2：CWA 觀測回波圖層 ＋ 時間軸
- 做什麼：
  1. 載入時 fetch `Observe_radar.js`（純 JS 檔，用正則或 `new Function` 取出 `RadarImg`），
     取 `size0` 底下的影像清單（`CV1_3600_YYYYMMDDHHMM.png` ＋ 時刻文字），通常是過去 ~3 小時、每 10 分鐘。
  2. 用 `L.imageOverlay('https://www.cwa.gov.tw/Data/radar/' + img, CV1_BOUNDS, {opacity:0.6})` 疊圖。
  3. 時間軸：滑桿 ＋ 播放/暫停 ＋ 時刻標籤（台灣時間，標「觀測」）。只有過去→現在，沒有未來。
  4. 每 3 分鐘重抓 `Observe_radar.js`；沿用日本版「不打斷使用者捲動位置」的邏輯。
- 產出：可播放過去 3 小時的台灣雷達回波動畫。
- 注意：`Observe_radar.js` 可能有多個 Tab/Area/size，挑「臺灣鄰近範圍」那組（對應 `CV1_3600`）。

### Step 3：校準 CV1_3600 的地理範圍（逆向）
- 做什麼：先用一組候選 bounds（例如 `[[20.4, 117.3], [26.9, 123.8]]` 或
  `[[21.0, 118.0], [26.5, 123.5]]`）疊圖，把 imageOverlay 開到 opacity 1、
  跟 OSM 海岸線比對，微調 bounds 到台灣輪廓對齊（放大到台北港、鵝鑾鼻、蘇澳角幾個點檢查）。
  校準完把最終 bounds 寫死成常數 `CV1_BOUNDS`，附註釋說明怎麼得來的。
- 產出：回波圖跟底圖對齊。
- 注意：CWA 的圖是等經緯度投影（Plate Carrée），Leaflet 預設 Web Mercator——
  緯度越高偏移越大。若對不準考慮用 `L.imageOverlay` 的替代（`Leaflet.ImageOverlay.Rotated` 不需要；
  純平移縮放通常夠，台灣緯度跨度小）。真的不行退而用 `L.TileLayer` 包一層或 `distortableImage`。

### Step 4：「你頭上目前」＋ 雨帶目測輔助
- 做什麼：
  1. 沿用日本版 canvas 取樣——把當前 CV1 圖畫到離屏 canvas，讀使用者 GPS 座標對應像素的顏色，
     配 CWA 雷達色階（dBZ → 顏色，需另外對照 CWA 色階表）判斷「你頭上目前：無雨／小雨…」。
     ⚠️ CWA 圖是否送 `Access-Control-Allow-Origin` 要先測；沒有的話 canvas 會 tainted，
     這個功能就降級成「看地圖上的點」。
  2. 幽靈點改義意：v1a 沒有未來雷達，所以幽靈點只在「跟著 GPS 移動時」顯示一個
     「照現在方向速度，10/20/30 分鐘後你在這」的參考點（不綁時間軸），純幫你對照雨帶。
- 產出：頭頂雨況文字（若 CORS 允許）＋ 前方位置參考點。
- 注意：CWA 色階跟 JMA 不同，要新做一張對照表（藍→綠→黃→紅→紫，dBZ 15–65）。

### Step 5：騎乘體驗細節（沿用日本版）
- 做什麼：CWA 雷達色階圖例、Wake Lock、深色底圖、大按鈕下緣資訊列、
  「資料：中央氣象署 整合雷達回波圖」標註與更新時刻。
- 產出：可實際騎乘使用的介面。

### Step 6：部署到 GitHub Pages
- 做什麼：`git init`、建 repo `ymeroom/biking-gps-weather-tw`（public）、push、開 Pages、
  手機實機測試（允許定位、加到主畫面）。push 前確認 repo 名稱、確認沒把測試雜物加進 commit。
- 產出：`https://ymeroom.github.io/biking-gps-weather-tw/`

### === v1b（等你申請 CWA opendata 免費 API key 後）===

### Step 7：研究 opendata 能拿到的短期降雨預報
- 做什麼：拿到 key 後查 datastore 目錄，鎖定最適合的產品：
  優先看鄉鎮天氣預報（`F-D0047-*`，逐 3 小時、有降雨機率）、
  定量降水預報 QPF、或劇烈天氣即時預報。確認更新頻率、涵蓋時數、資料形式（JSON 網格 or 點）。
- 產出：一份「用哪個產品、怎麼接」的小結。

### Step 8：加「路線前方降雨」文字面板
- 做什麼：用 GPS 目前位置（或日本版那種方向速度外推的未來位置）反查所在／前方鄉鎮，
  顯示「XX 區 未來 3 小時：降雨機率 70%、預估雨量 5–15mm」之類。放在下緣面板，跟雷達動畫並存。
- 產出：台灣版的「未來」資訊（文字，不是雷達動畫）。
- 注意：明確標示這是鄉鎮級預報、更新頻率低，跟即時雷達不同性質——別讓使用者誤以為是即時。

## 預計成果

- **v1a**：手機網頁，藍點跟騎，CWA 官方觀測雷達回波圖可播放過去 3 小時，看雨帶往哪移動；
  螢幕常亮、深色底圖、頭頂雨況（若 CORS 允許）。部署在 GitHub Pages。
- **v1b**：多一個「前方鄉鎮未來 1–3 小時降雨」文字面板。

## 不包含在這次的範圍

- 台灣以外
- 真正的「未來雷達回波動畫」（台灣沒有免費公開資料，做不到）
- 沿實際路線推算、離線快取、航跡記錄
- 跟日本版共用同一個 repo／同一份程式（兩邊資料源差太多，各自獨立）

## 可能遇到的風險

- **CWA `CV1` 圖沒有 CORS 標頭** → 「你頭上目前」canvas 取樣會失敗，降級成純看圖。先測、早知道。
- **imageOverlay 投影不合（等經緯度 vs Web Mercator）** → 台灣緯度跨度小通常可接受；
  對不準就微調 bounds 或換 distortable image 方案。
- **`Observe_radar.js` 格式改版** → 解析集中在一個函式，失敗時明確報錯。
- **CWA 網站擋跨站 hotlink（Referer）** → 部署後第一件事實機驗證圖有載入；必要時加 `referrerpolicy="no-referrer"`。
- **v1b：opendata 沒有夠即時／夠細的降雨預報產品** → 退而用鄉鎮 3 小時預報，並在 UI 誠實標示限制。
